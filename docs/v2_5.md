로컬 work 및 원격 work 모두 `c98c767`, 시작 작업 트리 clean을 직접 확인했다.

명시적 영역 인식·파일 IPC·crop/model/버전 해시 캐시·JSON/PDF 및 52개 테스트를 갖고 있다.
8GiB RAM 제한과 약27GiB 가용 디스크를 확인했다. 기존 V34/PP-FormulaNet-S/OCR 가중치를 재사용한다.

사용자 구안은 목표이며 모델 이름/도메인/자원과 실제 결과를 확인하면서 적용한다.
B0를 기본으로, RGB를 보존한다. B3는 이전 실험을 보존하고 새 주력 평가에서는 제외한다.

- oracle ROI에서 S → plus-S → L 순서로 비교하고 중요한 실패가 남을 때 UniMERNet을 검증한다.
- 런타임 모델 선택은 명시적인 설정이며 평가용 정답을 사용하지 않는다.
- 자동 레이아웃과 OCR의 충돌은 unknown/needs_review로 보존한다.
- 여러 줄 분할은 후보이며 분수/행렬/첨자 구조를 자동으로 확정하지 않는다.
- 원본 전체 예측과 분할 예측을 함께 저장하고, 결합은 명시적인 구조 hint일 때만 수행한다.
- 렌더링 성공은 문법/도구 호환성일 뿐 인식 정답 판정이 아니다.
- 실제 연속 영상이 없다면 합성 연동 smoke와 실제 정지 프레임 평가를 분리한다.

## 최종 구현 (2026-10-29)

`boardnotes.v25`는 기존 V1/V2 명령과 별도로 실행한다. 흐름은
영상 → V1 V34/ST3D 합성 키프레임 → PP-DocLayout-S + PP-OCRv5 Mobile
→ 보수적 영역 병합/분류 → 지정한 수식 모델/문자 OCR → JSON → 수식 렌더링/PDF다.
모델은 독립 subprocess에서 순차 적재하며, 기본 수식 모델은 PP-FormulaNet-S다.
실제 비교와 권장 근거는 [결과 문서](v2_5_results.md)에 있다.

### 설치 및 체크포인트

V1 환경은 기존 requirements를 유지하고 Paddle은 [V2 설치](v2.md)의 독립 환경을 재사용한다.
`requirements/v2-ocr.txt`의 버전을 사용하며 새 Python 추론 패키지는 추가하지 않았다.
수식 이미지 생성에는 시스템 `pdflatex`, `pdftoppm`, TeX `standalone`, `amsmath`,
`amssymb` 패키지가 필요하다. 이번 환경에는 이미 설치되어 있었다.
미설치/지원하지 않는 문법/컴파일 실패는 별도 rendering 상태로 기록하고 원문과 crop을 남긴다.
다중 키프레임 PDF 병합에는 기존 requirements-dev의 `pypdf`가 필요하다.

```bash
python scripts/v2_fetch_models.py --formula-model PP-FormulaNet-S --layout
# 필요 모델만 추가 다운로드한다. --formula-model은 반복 가능하다.
python scripts/v2_fetch_models.py --formula-model PP-FormulaNet_plus-S
python scripts/v2_fetch_models.py --formula-model PP-FormulaNet-L
python scripts/v2_fetch_models.py --formula-model UniMERNet
```

가중치와 다운로드 tar는 Git 제외 `models/v2`에 둔다. 공식 배포 URL, 아카이브/파일
SHA256은 `models/v2/models.json`과 [실험 provenance](assets/v25/model-provenance.json)에 기록했다.
다운로드 크기는 S 약224MiB, plus-S 약248MiB, L 약695MiB, UniMERNet 약1564MiB,
DocLayout-S 약4.9MiB다. V34는 기존 저장소 체크포인트를 사용한다.

### 실행

저장소 루트에서 실행한다. 아래 python은 V1 환경이며 `--ocr-python`만 Paddle 환경이다.

```bash
python -m boardnotes.v25 video lecture.mp4 --output output/v25-video \
  --ocr-python /path/to/paddle-env/bin/python \
  --v1-python /path/to/v1-env/bin/python \
  --formula-model PP-FormulaNet-S --fps 1 --max-width 1280 --split-formulas

python -m boardnotes.v25 image frame.png --output output/v25-image \
  --ocr-python /path/to/paddle-env/bin/python --formula-model PP-FormulaNet-L

python -m boardnotes.v25 manifest output/v1/v2_inputs/manifest.json \
  --output output/v25-manifest --ocr-python /path/to/paddle-env/bin/python

python -m boardnotes.v25 render output/v25-image/result.json --output reviewed.pdf
```

출력은 빈 디렉터리를 지정한다. 기존 실험 결과를 덮어쓰지 않는다.
`image --b0 aligned-mask.png`で既存V34二値画像を使える。寸法と0/255画素値を検査する。
通常のimage入力ではRGB全体を保存し、認識にはB0を使う。
動画manifestは時間合成B0であり、存在しないRGB対応を生成しない。
`--timestamp`の単位は秒、bboxは元入力のhalf-open `[x1,y1,x2,y2]`だ。

`image --regions edited-regions.json`は自動検出を省略する。自動出力の
`analysis/regions.json`をコピーし、領域type/bboxを直して新しい出力先で再実行する。
認識済み`content`/`latex`は再推論入力に使わない。crop/model/config/weights/versionが同じ
認識は共有`--cache-dir`から再利用する。文章や数式の手修正だけなら`render`でPDFを再生成できる。

### 自動領域と不確実性

`layout.py`は実SDKの座標/ラベル/scoreを正規化する。近接重複は併合し、
矛盾するlayoutラベルはunknownにする。包含OCRは出典として残すが、ページの大部分を占める
図領域や、数式記号を含むOCRを覆うtext/title領域には衝突ガードを設けた。
その場合は親とOCR候補を分けて保存する。OCRの`=`等と文章語数による簡単なルーティングは
提案に過ぎず、全てneeds_reviewを維持する。検出scoreと認識scoreは区別し、校正済み確率とは扱わない。
小さな孤立候補や分類できない図も破棄せずunknown画像として残す。
読み順はy帯とxの幾何ヒューリスティックで、意味上の数式順序の保証はない。

### 複数行、構造、レンダリング

`splitting.py`は連結成分/水平投影/空白から行候補を出す。行列、分数、根号、添字の
危険な分割は保留し、縦長の横括弧は解析マスクだけから除外する。元画像は変更しない。
`--split-formulas`で全体と行候補の両方を認識する。結合する場合は
`--hints hints.json`に`{"region_id":"aligned"}`または`cases`を明示する。
元画像にない等号や関係は補わず、結合結果もneeds_reviewとし全体予測を併記する。

LaTeXはコマンド/環境allowlist、括弧整合、文字数、時間/CPU/メモリ/ファイルサイズ制限で
検証し、shell escapeを無効にして描画する。画像ハッシュで描画キャッシュも検査する。
PDFは全体原画像、元crop、認識文、検索/コピー可能なliteral LaTeX、描画した数式を収録する。
`result.rendering.json`で認識状態と描画状態を別々に記録する。

### 出力と資源

image出力は`b0.png`, `analysis/regions.json`, `recognition/`, `result.json`,
`result.pdf`, `result.rendering.json`, `report.json`。
videoは`v1/`と`v25/page_*/`、統合`v25/result.pdf`、`end-to-end-report.json`を作る。
既存V2のschema version 2.0を保ち、metadata.versionに2.5を記録する。
`--threads`既定2、`--max-rss-mib`既定6000、`--timeout`は各workerの制限秒。
監視はworker PIDのRSSを測り、超過時はプロセスグループを終了し失敗を保存する。
子孫合算RSS/機器全体のメモリ上限を保証するものではない。
