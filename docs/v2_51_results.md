## 무엇을 구분했나

Strict EM의 불일치, 수식 내용/2차원 구조 오류, 렌더링 실패를 서로 다른 관측으로 기록했다.
예를 들어 `x^2`와`x^{2}`, `bmatrix`와대괄호로둘러싼`matrix/array`, `\ne`와`\neq`는
문자열이 달라도 같은 표현일 수 있다. 반면 원소가 바뀌거나 행/열을 잃는 출력은 실제 내용 오류다.
matrix cell 일치도 괄호 종류/구분선/다른 수식까지 보장하지 않으므로 의미 정확도로 부르지 않는다.

인쇄 대응본은 원본 V34 crop과 canvas 크기 및 전체 잉크 외접 영역을 근사했다.
폰트, 획, 개별 글자 크기, 자간/행 간격, 배경과 색상까지 완전히 통제하지 못했다.
따라서 인쇄/손글씨 대비는 입력 외형에 따른 민감도의 증거이며 특정 학습 데이터 구성의 증거가 아니다.

## 1. 인쇄 수식에서는 무엇이 가능한가

24개 통제식은 팩토리얼, 분수/중첩 분수, 2/3원소 열벡터, 2×2/2×3/3×3 행렬,
다중 행, 복합 첨자, 집합/자연어를 같은 TeX 폰트와180dpi로 생성했다.
모델별 전체 수치와 구조별 관측은 정량 부록에 따로 제공한다.
S/plus-S/L은 인쇄2×2/2×3/3×3 행렬과2/3원소 벡터에서 해당 행·열/원소를 보존했다.
네 모델 모두 인쇄3×3 행렬과 팩토리얼을 읽었다. 그러나 UniMERNet은 인쇄3원소 벡터에서도
`\binom{1}{2}`로 마지막 원소를 누락했고, 인쇄2×2/2×3 행렬에서는 행별 괄호 배치가 틀렸다.
이 오류는 손글씨만의 문제가 아니다. 더 큰3×3이 맞고 작은 행렬이 틀리는 비단조 사례다.
S는 확대행렬에서 문법 오류, plus-S는2행 등식의`3x=1`을`x=1`로 바꾸는 오류와
자연어 혼합의 text/수식 경계 오류가 있었다. 인쇄 이미지도 항상 성공하는 것은 아니다.
Strict EM만으로 인쇄 행렬의 성공 여부를 판단하면 wrapper 차이를 인식 오류로 세게 된다.
범용적인 구조 복잡도 임계점을 이24개 예시로 추정하지 않는다.

| 모델 | 인쇄 통제식 Strict EM | 실제 V34 Strict EM | 인쇄 대응본 Strict EM |
|---|---:|---:|---:|
| PP-FormulaNet-S | 8/24 | 5/18 | 4/18 |
| PP-FormulaNet_plus-S | 9/24 | 2/18 | 6/18 |
| PP-FormulaNet-L | 8/24 | 4/18 | 4/18 |
| UniMERNet | 7/24 | 5/18 | 5/18 |

이 표는 의미 정확도가 아니다. 인쇄에서도 `x_i`→`x_{i}`, `bmatrix`→`matrix`로 Strict EM이 낮아진다.
UniMERNet의 확대행렬은 두 array를 나란히 연결해 시각적으로 같은 행렬을 만들지만 제한적 parser의
flat matrix cell 비교는 false다. 이를 모델 오류로 확정하거나 parser 일치율로 모델을 순위 매기지 않는다.

## 2. 실제 판서에서는 어떤 오류가 남는가

실제 `p,q,r` 열벡터는 일부 출력에서 적분이나 분수로 바뀌고 원소/행이 사라진다.
순열 행렬은 행·열 개수가 바뀌거나0/1 원소를 누락/중복한다. 팩토리얼은 `!`를`1`이나
세로 막대로 읽는다. 이들은 환경/프로세스 실패와 다른 정상 추론 중의 인식 오류다.
이미지가 손글씨라는 사실만으로 원인을 학습 데이터 문제로 확정하지 않는다.
불규칙한 글리프/배치/획, 배경, 모델의 구조 해석이 함께 달라지는 실험이다.

기존 입력 벡터`[x,y,z]^T`에서 일부 모델의 출력은3행1열의 같은 원소를 다른 LaTeX 환경으로 썼다.
`AB\ne BA`를`AB\neq BA`로 쓴 출력도 표현 차이에 해당한다.
이와 달리 `B`가`\beta`로 바뀌는 출력은 내용 오류다. 전체 낮은 EM을 어느 한쪽으로 일괄 해석하지 않는다.
UniMERNet의 x/y/z 출력은 cell은 맞아도 짧은 대괄호가 가운데 행만 감싸는 배치 차이가 있다.

## 3. V34가 작은 기호를 지웠나

[점·획 감사 JSON](assets/v251/pixel-audit.json)과
[실제 내부 입력 미리보기](assets/v251/internal_previews/PP-FormulaNet-S/real__lecture_08_53016__b0__cardinality_factorial.png)를 확인했다.
팩토리얼 점의 고정 로컬 영역은 원 crop 기준`[153,71,172,93]`이며 V34 검정 픽셀142개가 남는다.
RGB의gray<128인146개 픽셀 중137개가 V34에도 남는다. gray<150에서는196개 중142개다.
밝은 threshold192는 배경도 포함하므로 이 비율을 segmentation 정확도로 보지 않는다.

점은 RGB, V34, 모델 내부 decode 미리보기에서 모두 보인다. 정규화는 이후 grayscale/affine 변환이므로
이진 입력의 점을 별도 제거하지 않는다. **이 사례의 `3!→31`을 점의 완전 소실로 설명할 수 없다.**
윤곽/면적/흐림이 달라지는 영향까지 없다는 뜻은 아니다.

다른 작은 기호가 항상 보존된다는 일반 보증도 없다. 이번 민감도5사례의 V34 원 crop은 경계에
검정 픽셀이 닿지 않지만, 전체18개에서는6개에 경계 접촉이 있었다. 접촉은 잘림의 경고일 뿐이며
어떤 수학 기호가 잘렸는지를 단독 판정하지 않는다. 원본 crop과 주변 확장 조건을 함께 보존했다.

## 4. Crop과 스케일은 얼마나 영향을 주나

민감도 대상은 연립방정식, 확대행렬, 문자 열벡터, 순열 행렬, 팩토리얼의5사례다.
RGB/V34에 각각 pad10/pad20/tight를 적용하고, 열벡터/팩토리얼은 cubic 2배도 비교했다.
pad는 각 변을 기존 폭/높이의10/20%만큼 확장한다. 조건별 결과는 정량 부록을 기준으로 본다.

실제 PaddleX 전처리는 스스로 min/max 정규화 threshold로 전경 외접 영역을 잘라낸다.
따라서10개의 외부 tight 입력은 네 모델 모두 baseline과 **정규화 tensor까지 동일**했다.
빈 흰 canvas만 늘린6개 인쇄식도 네 모델에서 원래와 같은 tensor가 됐다.
외부 여백이 달라도 모델이 같은 입력을 보는 경우가 있으므로, 이 조건을 독립적인 성능 개선으로 세지 않는다.

전체 이미지에서 pad하면 이웃 판서가 들어올 수 있다. V34에서20% 확장은 연립방정식에4124개,
순열 행렬에1427개, 팩토리얼에1292개의 검정 픽셀을 기존 bbox 밖에서 추가했다.
이 픽셀은 이웃 글씨/획 연장일 수 있어 모두 noise로 부르지 않는다.
실제 ROI를 넓혀 의미상 다른 수식을 포함하는 조건은 GT 영역 자체와 어긋날 수 있는 스트레스 테스트다.
2배 확대도 이미 손실된 정보의 복원이 아니며 내부 resize에 다시 들어간다.

모든 모델에서 선택5사례의 원래/RGB/V34/pad10/pad20/tight와 선택2사례의2배 확대는
각 조건별 전체 수식 Strict EM이0이었다. 이는 부분 개선도 없다는 뜻은 아니다.
UniMERNet 순열 행렬의pad10은 RGB/V34 모두 아홉 원소와 행·열을 복구했다.
그러나 RGB는 array가2열을 선언하고 실제로3열을 내보내 렌더링에 실패했다.
V34는 올바른 행렬 뒤에`1`을 추가했다. 확장 입력에 실제 인접 획이 들어오므로 이`1`을
근거 없이 hallucination으로 단정하지 않는다. 원래 수식의 완전한 복구로도 세지 않는다.
이 두 사례는 별도 시각 검토에 포함했다.

빈 canvas의 효과와 극성도 다르다. 흑백 반전한 인쇄3×3/팩토리얼2개는 네 모델 모두 Strict EM0/2였고
일부는 내용을 완전히 바꿨다. L의 반전 팩토리얼 출력`B\equiv(0)`는 렌더링에는 성공한다.
렌더링 성공으로 인식 정확성을 판단할 수 없는 구체적인 예다.

## 5. 2차원 구조의 실패 원인

벡터와 분수의 혼동, 행렬의 행/열 누락은 실제 구조 오류로 분리했다.
인쇄된 여러 구조를 읽을 수 있다는 관측과 실제 판서에서 그 구조를 안정적으로 읽는다는 주장은 다르다.
이번 작은 표본에서 입력 구조가 커질수록 오류가 단조 증가한다고 주장하지 않는다.
특히 여러 줄 정렬, 확대행렬 구분선, 수식과 자연어 혼합은 원소 인식과 별도 문제가 된다.
행렬 cell 일치와 세로 구분선 수를 따로 기록했다. 렌더링이 성공해도 둘 중 하나가 틀릴 수 있다.

## 6. 분할과 재결합으로 무엇을 개선할 수 있나

원본 전체 예측, 고정 행 crop 예측, 명시적 aligned 재결합을 모두 저장했다.
실제2행 연립은 V2.5의 같은 두 crop으로 재검증했고, 인쇄2행/3행도 비교했다.
행 crop의 GT는 평가에만 쓰며 결합할 때 새로운 등호나 관계를 추가하지 않는다.
정확한 구조 hint가 있는 진단이며, 임의의 판서에서 구조를 자동 인식했다는 결과가 아니다.
실제2행 연립의 각 행은 네 모델 모두`3x=1`, `x+2y=3`으로 재인식했다.
인쇄2행/3행도 분할했으며, 실제·인쇄 합계7개 진단 행 ×4모델의28개 행 문자열이 모두 일치했다.
이 중 인쇄 전체가 이미 내용을 보존한 모델도 있으므로28건을 모두 성능 향상으로 세지 않는다.
plus-S의 인쇄2행 계수 누락은 분할 후 복구됐다. 재결합은 aligned 후보이며 원본 오른쪽 중괄호까지
자동 복원하거나 전체 수식 Exact Match를 달성했다는 주장은 하지 않는다.

행렬2×2의 행 단위 crop은 일부 모델에서 각 행을 별도의 괄호 행렬로 읽었다.
이를 aligned로 붙이면 원 행렬이 되지 않으므로 실제 적용을 허용하지 않는다.
[실제 V2.5 geometry probe](assets/v251/split-geometry.json)에서는 분수/중첩 분수와 행렬의
자동 분할을 보류하고, 인쇄2행/3행 등식에는 각각2/3개 행 후보를 냈다.
oracle 보호 hint와 hint 없는 결과를 별도 기록했다.

배포 기본값을 바꿀 근거는 없다. 확인된 다중 행 개선은 기존 V2.5의`--split-formulas`와
명시적`aligned` hint를 통해 선택적으로 활용할 수 있다. 여백/확대 자동 재시도나
정답 기반의 조건 선택은 추가하지 않았다.

### 선택적 확장 후보 옵션

부분적인 cell 복구를 실제 검토 경로에서 비교할 수 있도록 V2.5에
`--formula-context-margin 0.1`을 추가했다. 기본0이며0~0.5를 허용한다.
원래 formula bbox/예측을 유지하고 넓어진 bbox의`__context` 후보를 추가한다.
후보는 review_required이며 이웃 글씨 유입 가능성과 source_parent_id를 JSON에 기록한다.
후보 중 어느 쪽이 정답인지 자동으로 고르지 않는다. 기본 파이프라인의 인식 입력은 그대로다.

[실제 통합 검증](assets/v251/optional-context.json)에서는 UniMERNet으로 원래 순열 행렬과
10% 확장 후보를 함께 처리했다. 두 crop의 PNG SHA256 및 두 예측 문자열이 고정 진단 실험과
동일함을 확인했다. 이2개 추가 추론은 진단516건과 별도다. 전체 정확도 개선이 검증된 기본값으로
소개하지 않으며, 확인된 개선 적용은 기존 행 분할 옵션과 이 검토용 후보 보존에 한정한다.

## 7. 표현 차이와 실제 오류를 어떻게 판정했나

모든 예측에 Strict EM/edit distance, 렌더링 상태, 행렬 행·열/cell, 첨자 marker/value 순서,
팩토리얼 수, 다중 행 보존 관측을 기록했다. 첨자 sequence 일치는 부착 대상의 완전한 AST 검증이 아니다.
별도 시각 검토는 선택된 진단 사례이며, 독립 인간 판정자 합의나 전체 의미 정확도로 표현하지 않는다.
자동으로 확인할 수 없는 일반 수학 동치는`unknown`으로 남긴다.
정답과 예측의 raster IoU는 해상도/획/자간에도 영향을 받으므로 의미 정답 임계값을 두지 않았다.

직접 시각 검토는23개 입력 ×4모델,92건이며 코딩 에이전트의 단일 검토다.
기존 V2.5의 낮은 EM 중 선택한 V347사례 ×4모델의28건을 분해하면:

모두 Strict EM은 false인28건이다. 결과를 본 뒤 고른 진단 사례이며 전체 예측에서의 비율을 추정하지 않는다.
표현 차이를 실제 내용 오류에 합치지 않고, 보류 사례를 정답으로 처리하지 않았다.

## 검증과 한계

기존131개 + 신규7개, 총138개 테스트가 통과했다. 모델 추론 품질은 fixture와 구분했다.
현재 환경의 네 모델 파일12개를 기존 공식 배포 manifest SHA256과 대조했다.
모델 내부 전처리516개 tensor의 shape/hash를 기록했다. 신규 모델/패키지는 설치하지 않았다.
사용자에게 보이는 기본 V2.5 동작과 기존 데이터는 유지한다.

이 실험은 작은 개발용 진단이다. 조건별 성공을 사후로 조합하거나 의미 판정을 일반화하지 않는다.
핵심적인 후속 과제는 인쇄/판서의 글리프·간격·획·배경을 각각 통제하는 추가 실험과,
독립 판정자가 확인한 구조 GT다. 이번 근거만으로 학습 데이터 구성이나 모델 내부 attention의
특정 결함을 원인으로 단정할 수 없다.
