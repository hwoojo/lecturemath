  ```sh
  cd ACCESS2021_release
  python test_FCN_binarizer.py configs/FCN_LectureNet.conf /path/to/V34.dat frame.png output
  ```

  기본 설정은 CUDA=True이다. CPU 실행은 설정 복사본의
  `FCN_BINARIZER_USE_CUDA=False`가 필요하다. 새 어댑터는 설정 원본을 바꾸지 않고 CPU를 사용한다.
- 기본 모델 경로 조합: `OUTPUT_PATH` + `BINARIZATION_FCN_LECTURENET_DIR` +
  `BINARIZATION_FCN_LECTURENET_FILENAME`, 즉
  `ACCESS2021_release/lecture_data/output/models/LectureNet_model_BIN.dat`.
  V34 다운로드 링크는 공식 README에 있으나 파일은 없다. `torch.load` state_dict를
  `CreateFromConfig(config,3,False)` 모델에 `load_state_dict`한다.
- 입력: PIL RGB → `prepare_image`, tensor float, 채널별 `(x-.5)/.5`, 배치 1.
  고정 448×252 입력 제한은 없다. `binarize`만 2,500,000 픽셀 초과 시 절반씩 축소한다.
  1280×720 / 1920×1080은 축소되지 않는다. 모델 내 pooling/upsampling은 기존 구조 그대로다.
- 출력: `forward()`는 binary logit, text-mask logit, reconstruction tensor.
  binary logit은 아직 sigmoid가 아니다. `binarize()`에서 sigmoid → ×255 → uint8 →
  임계값 128로 0/255를 만든다. `force_binary=False`도 이미 8비트 양자화된 값이므로
  새 B4는 forward에서 확률을 직접 가져온다.
- **중요한 극성**: 학습 dataset의 `gt_t=TF.to_tensor(pil_gt)`이며 GT는 검정 판서다.
  따라서 binary sigmoid는 **배경 확률**이고 기존 이미지 CLI 결과는 검정 판서/흰 배경이다.
  영상 worker는 이 결과를 `255-binary`로 뒤집어 흰 판서로 저장한다.
  영상 worker/debug PNG에는 `--baseline-polarity light`, 이미지 CLI `_BIN.png`에는
  `--baseline-polarity dark`를 쓴다. 외부 파일 이름은 원본 stem에 맞춰야 한다.
- 체크포인트/실제 영상/실제 RGB 강의 프레임/검증된 V34 캐시/픽셀 GT는 발견되지 않았다.
  외부 `/workspace/lecturemath-local/artifacts`에는 64×64 흰 입력과 **미학습 합성 모델**
  결과가 있다. 이를 V34나 강의 품질 근거로 사용하지 않았다.

## 구성 및 방법

`experiments/v1_5/`는 기존 V1에서 import되지 않는 독립 모듈이다.
추가 설치 없이 기존 NumPy/OpenCV로 실행한다. Torch/Pillow/torchvision은
명시적으로 checkpoint 추론을 선택할 때만 필요하다. 학습/역전파/가중치 수정은 하지 않는다.

| 비교군 | 구현 | 입력·제약 |
|---|---|---|
| B0 | 기존 이진 PNG 재사용 또는 V1과 같은 CPU 추론 | PNG와 RGB 좌표·크기가 같아야 함 |
| B1 | grayscale + 선택적 Gaussian Blur + OpenCV Otsu | 원본 RGB, 전경 극성 명시 |
| B2 | Sauvola, R=128, 국소 평균/표준편차 | window 25/51, k .2/.35 기본, 선택적 CLAHE |
| B3 | `B0 OR (dilate(B0) AND Sauvola)` | radius=2 기본, B0 판서 보존, 확장 밖 추가 금지 |
| B4 | 동일 float 판서 확률에 .35/.5/.65 임계값 | 추론 1회 재사용 또는 외부 float NPY; 이진 입력 거부 |

Sauvola는 OpenCV boxFilter(float64), replicated border로 구현했다.
scikit-image와 가장자리 규약이 다를 수 있으므로 구현 이름과 설정을 유지해 비교해야 한다.
밝은 판서는 원본 grayscale을 반전한 뒤 동일 알고리즘을 적용한다. 자동 극성 추정은 제공하지 않는다.
B3는 완전히 놓친 독립 영역을 복원하지 못하며, 모델이 교수자/경계를 이미 검출했다면
그 주변의 오검출도 확장할 수 있다. 단순 마스크 연산이므로 물체 제거 보장은 없다.

B4 어댑터는 `p_writing=1-sigmoid(binary_logit)`를 제공한다. B0는 기존 양자화와
128 임계값을 정확히 보존한다. 따라서 B4의 0.5와 B0 경계는 양자화 때문에 미세하게 다르다
(B0는 배경 확률 `<128/255`, 즉 판서 확률 `>127/255`). B0를 B4로 대체하지 않는다.
2.5MP 초과는 V1처럼 축소 후 B0 nearest/B4 cubic 복원을 하며 B4 확률은 [0,1]로 제한한다.
기본 비교는 이 정책에 해당하지 않는 720p/1080p 원본을 권장한다.

## 실행

저장소 루트에서 실행한다. 이 환경의 Python은 `/workspace/lecturemath-env/bin/python`이다.
임의 패키지 업그레이드나 모델/데이터 다운로드는 수행하지 않았다.

```sh
# 체크포인트 없이 독립 비교군; 기본 최대 5장
python -m experiments.v1_5.cli /data/frames --output /tmp/v15_direct \
  --polarity dark --methods B1 B2 --limit 3 --resolution 1080p

# 기본 전체 비교: 사용 불가능한 B0/B3/B4는 사유와 함께 skip
python -m experiments.v1_5.cli /data/frames --output /tmp/v15_available \
  --polarity dark --limit 3

# 기존 V1 PNG 재사용: frame001.png ↔ baseline/frame001.png
python -m experiments.v1_5.cli /data/frames --baseline-dir /data/baseline \
  --baseline-polarity dark --output /tmp/v15_cached --polarity dark \
  --methods B0 B1 B2 B3 --roi 100,80,1400,800 --crop 300,200,240,120 --zoom 4

# 밝은 판서, Sauvola/CLAHE/확장 폭 비교 (필요한 후보만 선택)
python -m experiments.v1_5.cli /data/chalk --output /tmp/v15_chalk \
  --polarity light --baseline-dir /data/baseline --baseline-polarity light \
  --windows 25 51 --ks 0.2 0.35 --clahe both --radius 2 --blur 0 3

# V34가 준비된 환경: CPU, 추론 결과 캐싱, B0/B4는 동일 forward 사용
python -m experiments.v1_5.cli /data/frames --output /tmp/v15_model \
  --polarity dark --checkpoint /models/LectureNet_model_BIN_V34_final.dat \
  --config ACCESS2021_release/configs/FCN_LectureNet.conf \
  --cache-dir /tmp/v34_cache --threads 2 --limit 3

# 외부 연속 출력: float .npy, shape H×W, 판서 확률 [0,1]
python -m experiments.v1_5.cli /data/frames --output /tmp/v15_thresholds \
  --polarity dark --methods B4 --probability-dir /data/writing_probabilities \
  --thresholds 0.35 0.5 0.65

# 검증용 GT는 0/255 PNG; baseline을 실제 정답으로 대용하면 안 됨
python -m experiments.v1_5.cli /data/frames --output /tmp/v15_gt \
  --polarity dark --methods B1 B2 --gt-dir /data/ground_truth --gt-polarity dark

# 재현 가능한 기능 검증 및 저장된 합성 출력 재생성
python -m unittest discover -s experiments/v1_5/tests -v
python -m experiments.v1_5.synthetic_demo
```

`--resolution native`가 기본이다. `720p`/`1080p`는 입력 해상도 **검사**이며 resize하지 않는다.
720p와 1080p는 각각 같은 원본 프레임 집합을 모든 비교군에 전달해 따로 실행한다.
다른 해상도 간에는 원본 영상의 동일 시점 프레임임을 별도로 확인해야 한다.
ROI/crop은 `x,y,width,height`, 현재 입력의 픽셀 좌표다. ROI는 평가에만 적용하고
출력 전체 프레임은 보존하므로 ROI 밖 오검출도 육안으로 볼 수 있다.
ROI를 빼고 실행하면 전체 영역 지표를 얻는다.

## 출력 및 신뢰성

- 이미지 단위 순차 처리; 원본 PNG, 각 비교군 PNG(검정 전경), GT(있을 때), Contact Sheet.
- Contact Sheet는 메모리 절약을 위해 기본 좌상단 320×180 crop, 2배 확대를 사용한다.
  관심 획이 포함되도록 `--crop`으로 지정한다. 각 비교군을 세로로 나열하며 nearest-neighbor 확대한다.
- `metrics.json`: 전체 CLI 설정, Python/OS/패키지 버전, 입력 SHA256·shape,
  외부 baseline/확률/GT 해시, skip 사유, 각 알고리즘 지표 및 시간.
- 추론 캐시는 RGB 파일/체크포인트/설정 SHA256 + adapter version으로 구분한 NPZ다.
  이미지 포맷만 바뀌어도 보수적으로 새 캐시를 만든다. 외부 PNG/NPY는 좌표/극성/출처를
  사용자가 확인해야 한다. 크기만 같다고 정렬이 증명되지는 않는다.
- GT가 없으면 precision/recall/F1/IoU 키 자체가 없다. 전경 비율, 8-connected component 개수,
  크기 분포(min/Q25/median/Q75/max)는 품질 지표의 대용이 아니다.
  GT shape 검증, ROI가 비어 있는 경우 오류, 분모 0일 때 지표 0 규약을 적용한다.
- `postprocess_seconds`: 알고리즘 연산만 포함, PNG/지표/Contact Sheet I/O 제외.
  B0는 복사이므로 0이며 실제 추론 시간과 혼동하면 안 된다. 추론 시간은 별도 필드에
  모델 생성/체크포인트 로딩/캐시 I/O까지 포함해 기록한다. 이미지 전체 시간도 별도다.
- Linux process peak RSS는 프로세스 시작 이후 누적 최고치이며 비교군별 메모리가 아니다.
  비교군별 정밀 메모리/통계적으로 안정된 벤치마크는 수행하지 않았다.
- 출력 디렉터리 재사용 시 이전 PNG가 남을 수 있다. 현재 실행의 공식 목록은 metrics.json이다.
  비교 실험마다 별도 출력 디렉터리를 권장한다.

실제 프레임 추출/영상→키프레임→PDF 전체 실행은 자산/래퍼 부재로 수행하지 않았다.
새 CLI는 정지 프레임 실험 범위이며 기존 영상 파이프라인을 변경하지 않는다.
OCR, Whisper, 추가 신경망, fine-tuning은 포함하지 않는다.
