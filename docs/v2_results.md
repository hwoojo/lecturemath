# V2 실행 결과와 한계

2026-10-28, `work` 브랜치. V1/V1.5 기준 커밋 `ad45dc4` 이후의 로컬 개발 결과다.
이 보고서의 인식 결과는 **실제 Paddle CPU 추론**에서 얻었으며 mock 결과가 아니다.
기존 기술명 비교 PDF의 미커밋 변경은 보존했다.

## 구현 및 검증 범위

- Phase A: 원본 좌표에서 text/formula 영역을 지정하고 crop, 독립 모델 추론, RGB/B0/B3 비교를 수행했다.
- 실제 PP-OCRv5 Mobile 텍스트 검출·영문 인식과 PP-FormulaNet-S LaTeX 출력을 확인했다.
- 원본 이미지, 영역 crop, Unicode/LaTeX JSON, 검색·복사 가능한 PDF 결과 페이지를 저장했다.
- JSON 수정 후 재추론 없이 PDF를 생성할 수 있다. 모델별 subprocess, 디스크 캐시, 시간·RSS 기록을 지원한다.
- Phase B: 실제 전체 프레임에서 OCR 후보 영역 JSON을 생성했다. **신뢰할 수 있는 텍스트·수식 자동 분류는 아니다.**
- V1의 선택 옵션 `--export-v2-inputs`로 PDF 여백 제거·smooth 처리 전의 키프레임과 시간·좌표 정보를 내보낸다.

신뢰할 수 있는 자동 영역 분류, 복잡한 손글씨 수식 인식, LaTeX의 시각적 수식 조판,
원본 위의 검색용 비가시 텍스트 레이어, 한국어 실측, 실제 연속 영상의 전체 V2 처리,
V3 Whisper는 구현 또는 검증이 완료되지 않았다.

## 모델과 실행 환경

독립 환경 `/workspace/lecturemath-v2-env`를 사용했다. Python 3.12.14,
PaddlePaddle 3.2.2, PaddleOCR 3.3.2, PaddleX 3.3.11, NumPy 1.26.4,
opencv-contrib-python 4.10.0.84다. 기존 V1의 Torch 2.5.1+cpu/OpenCV 환경은 업그레이드하지 않았다.

공식 배포처에서 경량 텍스트 검출·영문 인식 모델과 PP-FormulaNet-S의 inference artifact
세 개를 받았다. 학습 데이터셋이나 대형 대체 모델은 받지 않았다.
[파일 출처와 SHA256](assets/v2/model_provenance.json)을 기록했으며 가중치는 Git에 포함하지 않는다.
사용자 확인에 따라 **간단한 인쇄 수식용 S 모델**로 손글씨의 한계를 먼저 검증했다.
더 큰 L 모델이나 UniMERNet/pix2tex로 임의 교체하지 않았다.

최초 Formula 초기화에서는 `tokenizers` 누락을, 이를 보완한 뒤 예측 과정에서는 `ftfy` 누락을
확인했다. 두 패키지는 독립 환경에만 추가했다. 보완한 의존성과 regex 버전은
`requirements/v2-ocr.txt`, 전체 환경은 `requirements/v2-ocr-lock.txt`에 기록했다.
최종 실제 실행에는 초기화 실패가 없었다. 이전 실패 로그는 `benchmark-output/v2/`에 보존했다.

## 데이터와 평가 방법

V1.5에서 사용한 AccessMath2015 실제 1080p 프레임 세 장을 재사용했다.
대상은 lecture_01/10423, lecture_02/44601, nm_lecture_01/19899다.
공개 출처와 원본·GT SHA256은 [V1.5 데이터 기록](assets/v1_5_real/metrics.json)에 있다.

각 프레임에서 영문 제목 한 영역, 간단한 손글씨 등식 한 영역, 여러 줄 수식 또는 분수 한 영역을
수동 지정했다. 같은 영역을 RGB, V34 B0, guided Sauvola B3 순으로 같은 모델에 입력해
**총 27개 예측**을 얻었다. B3는 window=25, k=0.2, radius=2, CLAHE off로 고정했으며
이번 인식 점수를 기준으로 파라미터를 조정하지 않았다.

영역 좌표와 수동 정답 전사문은 모델 실행 전에 지정했다. 전사문은 평가에만 사용하고
모델에는 입력하지 않았다. 텍스트는 소문자화·공백 접기 후 문장부호를 유지했다.
LaTeX는 공백만 제거해 엄격한 Exact Match와 편집 거리를 계산했다.
수학적 동치성에 대한 평가는 아니다. 별도 영상 개선이나 추가 resize를 적용하지 않았으며
입력 후보별로 서로 다른 처리를 하지 않았다. 모델 내부 전처리는 공식 구현을 그대로 사용했다.
시간은 알 수 없으므로 `timestamp=null`로 기록했고 프레임 번호에서 추정하지 않았다.

모델의 `status=ok`는 비어 있지 않은 출력이 나왔다는 뜻이며, 수식이 맞다는 뜻이 아니다.

## 소규모 표본 결과

| 입력 | 영문 제목 3개의 macro CER — 낮을수록 좋음 | 수식 영역 6개의 엄격한 LaTeX 일치 |
|---|---:|---:|
| RGB | 13.61% | 4/6 |
| B0 | 4.84% | 5/6 |
| B3 | 4.84% | 5/6 |

이번 표본에서 B0와 B3의 인식 출력은 모두 같았다. 일반적인 장면에서도 항상 같다는 뜻은 아니다.
영문 제목은 세 개, 수식은 여섯 영역뿐이다. V34 학습 포함 여부를 확인하지 못했고,
개발 표본과 독립 평가 표본도 분리하지 않았다. 이 수치를 데이터셋 전체 정확도,
OCR 일반화 성능이나 통계적으로 유의한 개선으로 해석하지 않는다.

### 확인한 성공·실패 사례

- `3x=1`, `x+3y=4`, `3x-y+z=7`은 세 입력에서 모두 같은 정답을 출력했다. 이 세 등식의 일치는 9/9다.
- 작은 분수 `y=\frac{27}{19}`도 세 입력에서 모두 정답 전사와 일치했다.
- 두 줄 연립방정식은 실패했다. RGB는 `3+2y=33`, B0/B3는 `3left+x=1\\right\\`를 출력했다.
  실행 오류 없이 비어 있지 않은 문자열을 반환했더라도 올바른 두 줄 구조가 아니다.
  원본 crop을 보존했으며 수식 결과는 사람이 검토해야 한다.
- 긴 분수 식의 RGB 출력은 `=\frac{8}{6}`를 한 번 더 반복했다. B0/B3는 이번 전사문과 일치했다.
  반복 항목은 문자열 Exact Match에 영향을 주지만, 이는 수학적 동치성 판정과 별개다.
- RGB의 영문 `Multiplication by a`는 `Multidication`으로 출력됐다.
  B0/B3는 `Multidication by a`를 출력했다. 모델 점수가 높더라도 철자는 틀릴 수 있다.
- 초기 구현은 Paddle이 반환한 영역 순서를 그대로 연결해 `Equations.`를 `System of Linear`보다
  앞에 놓은 적이 있다. 기하적 행 그룹화와 왼쪽→오른쪽 정렬을 적용한 뒤 모든 영역을 다시 실측했다.
  엔진의 원문과 반환 순서도 보존했다. 현재 정렬은 기초 휴리스틱이며,
  여러 열·위첨자·분수의 의미적 읽기 순서를 이해하는 기능은 아니다.

[전체 예측·전사·좌표·계수 JSON](assets/v2/comparison.json) · [CSV](assets/v2/comparison.csv).
실제 예측을 mock이나 사람이 고친 정답으로 대체하지 않았다.

## 자원 측정

텍스트 worker가 종료된 뒤 수식 worker를 시작했다. 두 작업의 모델을 같은 프로세스에
동시에 올리지 않았다. 각 worker는 같은 프레임의 RGB/B0/B3 crop을 차례로 처리했다.

아래 load는 Python 모듈 import와 모델 초기화를 포함한다.
process는 load와 해당 worker의 모든 crop 추론을 포함한다.
RSS는 worker 프로세스의 누적 최고치이며 crop별 사용량이나 모델 가중치의 순수 메모리가 아니다.

| 프레임 | 텍스트 load/process 초 | 텍스트 peak MiB | 수식 load/process 초 | 수식 peak MiB |
|---|---|---:|---|---:|
| lecture_01_10423 | 2.97/4.46 | 533.3 | 9.87/14.67 | 878.8 |
| lecture_02_44601 | 2.60/5.63 | 530.7 | 8.09/12.92 | 889.5 |
| nm_lecture_01_19899 | 3.00/4.86 | 542.8 | 9.10/13.79 | 878.8 |

최초 로딩을 포함한 단일 실행 측정이다. crop별 predict 시간은 JSON의 `seconds`에 있으며,
안정적인 처리량을 보장하는 벤치마크로 해석하지 않는다.
별도로 실제 CLI에서 첫 표본의 두 영역×세 입력을 재실행했고,
결과 여섯 개 모두 `cache_hit=true`였으며 모델을 다시 로딩하지 않았다.
캐시 재현성은 이번 고정 환경에서 확인한 범위이며 다른 라이브러리 버전·하드웨어의
픽셀 또는 문자열 단위 동일성을 보장하지 않는다.

## 자동 영역 제안과 V1 호환성

실제 lecture_01 전체 프레임에서 후보 영역 15개를 얻었으며 모두 `unknown/needs_review`로 기록했다.
수식·그래프·자연어 여부를 자동으로 확정하지 않았다. 사용자가 JSON의 유형과 bbox를 수정한 뒤
지정 영역 인식을 실행할 수 있다. [후보 JSON](assets/v2/auto_regions.json)을 제공한다.
그래프와 후보 영역 밖의 픽셀도 완전한 원본 이미지에 남는다.

V1 exporter는 기본값이 `False`이므로 기존 PDF 흐름은 바뀌지 않는다.
내보내기를 켜도 V1 PDF로 전달하는 이미지·시간·style이 같다는 것을 테스트했다.
내보낸 키프레임은 시간적 합성 결과이므로 단일 RGB 프레임과 대응한다고 가정하면 안 된다.
scale로 영상의 기하 좌표에 매핑할 수는 있지만, 같은 RGB 프레임에 복원된 모든 획이
존재한다는 보장은 아니다. 실제 연속 영상 전체의 ST3D→OCR 파이프라인은 이번에 재실행하지 않았다.

## 실무 권고와 다음 확인 사항

RGB와 B0를 계속 보존하고 B3는 전환 가능한 비교 후보로 유지한다.
이번 표본에서는 이진화가 일부 제목·분수 인식에 도움이 됐지만,
영문 제목 세 개와 수식 여섯 영역만으로 전체 입력 전략을 정할 수는 없다.

S 모델은 명시적으로 지정한 간단한 등식과 일부 분수의 초기 구조화에 사용할 수 있다.
**여러 줄 연립방정식이나 복잡한 손글씨 수식을 자동 확정·제공하는 용도로는 부족하다.**
현재 모든 수식 결과는 사람이 검토해야 한다. 복잡한 손글씨 지원을 계속하려면
영역 분할 전략이나 다른 모델의 자원 예산을 사용자와 먼저 확인한 뒤 진행해야 한다.
이번 작업에서는 모델을 임의로 교체하지 않았다.

다음에는 강의·필체·색상·작은 점·위첨자·아래첨자가 다양한 고정 평가 영역을 늘리고,
강의 단위로 개발·평가 표본을 분리해야 한다. 자동 수식 영역 분류, 한국어와 글꼴,
수식 렌더링, 실제 시간 구간을 갖는 ST3D 연계는 각각 별도의 검증이 필요하다.

재현 명령은 [v2.md](v2.md)를 참고한다. 전체 로컬 로그·모델 worker 응답·추가 PDF는
`benchmark-output/v2/`에 있으며 모델 가중치는 커밋하지 않는다.
