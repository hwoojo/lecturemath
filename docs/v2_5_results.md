## 평가 조건

CPU, threads=2, PaddlePaddle 3.2.2/PaddleOCR 3.3.2/PaddleX 3.3.11, MKLDNN off.
V1 Torch와 별도 환경에서 모델별 subprocess를 순차 실행했다. 재학습하지 않았다.
주력 입력은 FCN-LectureNet V34이며 RGB를 함께 평가했다. B3는 이전 실험에 보존했다.

기존 회귀용 3프레임의 수식6개/텍스트3개와, AccessMath의 다른 강의06/07/08에서
추가한 3프레임의 22영역(텍스트10/수식12)을 구분한다. 새 주석은 추론 전에 고정했다.
새 강의가 모델의 사전학습에 포함됐는지는 알 수 없다. 공인 held-out 벤치마크가 아니다.
수식마다 RGB/V34를 비교하므로 독립 표본 수를 2배로 세지 않는다.
추가 프레임에는 행렬, 벡터, 위/아래첨자, 집합, 팩토리얼 등이 있으나 적분/시그마/루트/분수는 없다.
어려운 유형의 균형 잡힌 대규모 표본으로 해석하지 않는다.

## 수식: 사람이 지정한 ROI

Exact Match는 공백만 제거한 LaTeX 문자열 일치다. 의미적 동치 판정과 다르다.
실행 실패/빈 결과를 정답으로 세지 않는다. 아래 실행에서는 worker 실패가 없었다.

| 모델 | 회귀 RGB | 회귀 V34 | 추가 RGB | 추가 V34 |
|---|---:|---:|---:|---:|
| PP-FormulaNet-S | 4/6 | 5/6 | 0/12 | 0/12 |
| PP-FormulaNet_plus-S | 5/6 | 2/6 | 0/12 | 0/12 |
| PP-FormulaNet-L | 5/6 | 4/6 | 0/12 | 0/12 |
| UniMERNet | 5/6 | 5/6 | 0/12 | 0/12 |

추가 0/12는 의미 정확도 0%라는 뜻이 아니다. 예를 들어 `AB\ne BA.`의
`AB\neq BA.` 출력은 의미상 같은 부등식이지만 문자열은 다르다. 입력 열벡터도
`bmatrix` 대신 `\left[\begin{matrix}...`나`array`를 쓰면 불일치한다.
반면 여러 행을 누락하거나 열벡터를 분수로 바꾸는 실패, `3!`을`31`로 읽는 오류도 있다.
정답 전사문은 단일 작업자의 주석이며 독립 판정자 합의/전수 의미 채점은 수행하지 않았다.
따라서 표현 차이와 구조 오류를 비교 PDF/원문과 함께 검토해야 한다.
평가 후 정답을 모델 출력에 맞춰 고치거나 GT로 모델을 골라 재실행하지 않았다.

| 모델 | 추가24 crops 전체 프로세스 초 | 모델 로딩 초 | worker 피크 RSS MiB |
|---|---:|---:|---:|
| PP-FormulaNet-S | 43.30 | 10.19 | 886.7 |
| PP-FormulaNet_plus-S | 30.64 | 11.82 | 918.8 |
| PP-FormulaNet-L | 372.34 | 10.40 | 1717.6 |
| UniMERNet | 343.45 | 20.32 | 2348.1 |

정확한 로딩/영역별 시간은 JSON runs/predictions가 기준이다. 프로세스 시간에는 모델 로딩이 포함되며
캐시 없는 한 번의 실행이다. 크기·입력·출력 길이가 달라 단순 배수로 일반화하지 않는다.
기존14 jobs(전체12 + 분할행2) 프로세스 시간은 S20.35/plus15.91/L199.53/UniMER128.25초였다.

## 여러 줄 분할

기존 두 줄 연립방정식의 전체 영역은 네 모델 모두 올바른 전체 구조를 만들지 못했다.
L의 V34 출력은 두 줄을 포함하나 서로 다른 괄호 표현으로 나오고, 다른 모델은 주로 한 줄을 잃었다.
V34 projection/성분 기반 후보를 두 줄로 나누면 네 모델 모두 각각`3x=1`, `x+2y=3`을 인식했다.
명시적 aligned hint로 결합한 후보와 전체 예측을 모두 JSON에 보존했다.
이것은 1개 사례의 2개 행 성공이며 전체 연립방정식의 일반 성능으로 해석하지 않는다.
괄호/구조를 자율 복원했다고 주장하지 않으며 행렬/분수 분할은 보수적으로 보류한다.

## 실제 영상 End-to-End

기존 저장소에는 연속 영상 파일이 없고 정지 프레임/주석이 있었다. AccessMath 공개 키프레임은
추가 ROI 평가에 사용했다. 기존 YouTube 링크는 권한 확인 후에도 프록시 CONNECT403,
Box 데이터 링크는404였다. [조사 기록](assets/v25/video-discovery.json)에 다른 후보도 남겼다.

접근 가능한 [MIT OCW 공식 강의 페이지](https://ocw.mit.edu/courses/18-06-linear-algebra-spring-2010/resources/lecture-1-the-geometry-of-linear-equations/)의
[공식 다운로드](https://archive.org/download/MIT18.06S05_MP4/01.mp4)를 사용했다.
Gilbert Strang의 실제 칠판 강의이며 영상 약600~612초 요청 구간만 HTTP range로 추출했다.
전체92MB 영상을 저장하지 않았다. 실제 clip은359프레임, 11.9786초, 480×360, 29.970fps,
약10.27MB다. 시간은clip-relative이며 요청한 원강의 오프셋은 별도 기록한다.
음성은 제외했고 픽셀 보존 lossless H.264로 저장했다.

명령은 [구현 문서](v2_5.md)의video 인터페이스에서max-width480/fps1/S/split-formulas를 사용했다.
12샘플 → V34/ST3D 키프레임2개 → 자동 영역 검출/분류 → OCR/수식 → JSON → 통합PDF가
**57.74초**에 완료됐다. V1은25.89초/RSS635.32MiB, 두 키프레임 V2.5는21.44/8.99초였다.

- 첫 키프레임: formula1, unknown6. 두 번째: text1, unknown1.
- 런타임 인식 실패0. 수식1개는`x=j`로 출력되어 렌더링까지 됐다.
- 원판서에 대한 정확한 인식이라는 뜻은 아니다. 낮은 해상도, V34 손실, 검출/분류 오류가 있다.
  공식 수식/영역 GT가 없으므로 영상 CER/EM/검출 정확도는 산출하지 않았다.
- 초기 실행은 큰 doc_title 영역이 수식 OCR을 흡수해 수식0개였다. 이를 개발 사례로 삼아 충돌 가드를 수정했다.
  위 최종 재실행 영상은 수정에 사용된 개발 사례이며 독립 품질 평가가 아니다.
- 키프레임은 시간 합성이므로 정확히 대응하는 단일RGB나 타임스탬프를 만들지 않았다.

출처는 MIT OpenCourseWare/Prof. Gilbert Strang. OCW 페이지는CC BY-NC-SA4.0,
Archive 메타데이터는 CC BY-NC-SA3.0 US를 표시하며 버전 차이를 provenance에 기록했다.
원본10MB clip은 실험 폴더에만 두고 파생 키프레임/비교 PDF에 출처를 부기했다.

## 자동 영역 분석과 검증 범위

PP-DocLayout-S는 일반 문서 모델이다. 칠판에서 넓은 영역을doc_title/image로 오분류할 수 있다.
검출기 출처/충돌/모호한 OCR 후보를 저장하고unknown을 유지한다. 기호 기반 라우팅은
검토용 제안이며 정확한 수학 분류기가 아니다. 수동JSON수정과 캐시 재실행 경로를 유지했다.
추가22영역은 부분 주석이므로 전체 판서의 검출Precision/Recall을 계산하지 않았다.

다른 강의의 추가3프레임도 수동영역 없이 S/V34로 전체 실행했다.
[자동 분석 결과](assets/v25/automatic-results.json)에 전체 예측과 검출 근거를 보존했다.

| 프레임 | text | formula | unknown | 처리 초 |
|---|---:|---:|---:|---:|
| lecture_06_47799 | 13 | 5 | 13 | 75.82 |
| lecture_07_67415 | 3 | 4 | 25 | 70.94 |
| lecture_08_53016 | 4 | 1 | 10 | 36.39 |

각 실행의 worker 인식 실패는0이지만 unknown이 많고 검출 중복/과분할도 포함될 수 있다.
이 수는 예측 수이며 정답 영역 수/정확도를 의미하지 않는다.

기존52개를 포함한 **131개 테스트 통과**: API4개, 나머지127개.
구조/오류처리는fixture 테스트이고 모델 품질 근거는 위 실제 Paddle 실행으로 분리했다.
TeX allowlist/타임아웃/원본보존/좌표/중복ID/캐시/영역충돌/분수·행렬 분할 방지 등을 검증했다.
API TestClient는 실행 sandbox의 네트워크 권한을 활성화해 검증했다.

## 다음 판단
